# Compaction recall: the summary remembers what the conversation stood on

Context compaction replaces a long conversation with a summary. The summary records what was decided; it rarely records the memory-store entries the decision rests on, because those entries were never in the conversation — the agent looked them up turns earlier and moved on. After the compaction, the anchors are gone from the context even though the store still holds them: the next search can find the entries again, but nothing prompts the search, and the summary that everyone reads forward says "we fixed the flaky test" without the trail back to the session that learned why it was flaky.

At `session_before_compact`, the last few user messages of the window about to be summarized become a search query, and the hits are appended to `preparation.messagesToSummarize` as one `[memsearch memories]` message (`src/extension.ts`). The summarizer sees that message like any other and keeps the anchors it needs. One search per compaction, on the existing queue and timeout; a failed search appends nothing and never blocks the compaction. `PI_MEMSEARCH_COMPACT_RECALL=off` disables it.

The injection is a message mutation on the shared preparation object rather than a result, because that is the seam the host offers: a `session_before_compact` result can replace a compaction outright, and `CompactionResult` carries a summary, not an input extension. The preparation pi summarizes is the same object the hook receives, so appending to it is the portable form — it needs no host API and works on pi-family runtimes alike.

Considered alternatives:

- **A scratchpad-style handoff**: rejected in [`.out-of-scope/scratchpad.md`](https://github.com/espadat-studio/pi-memsearch/blob/master/.out-of-scope/scratchpad.md), and this is not it — no new store surface, no notes tool. That note left the door open for exactly this: a compaction handoff gap that materializes "is its own feature with its own name". This is that feature.
- **Rely on the post-compaction snapshot refresh**: the snapshot answers "what is true now" for turns going forward, but it is built from the daily file's tail, not from relevance to what was summarized, and it does not travel inside the summary itself. Sessions that resume from the summary alone — branches, exports, other agents reading the transcript — see the snapshot only if they run pi-memsearch.
- **Host-side `extraContext` in the compaction result**: some pi-family runtimes accept extra context lines for the summary prompt. Basing the feature on one fork's result shape would not run on pi; mutating the preparation needs nothing beyond the documented event.
- **Query the whole conversation instead of the last user messages**: the summarization window is already large; recall only needs enough phrasing to disambiguate what the window is about. The last few user messages carry that at the lowest token cost, mirroring what compaction itself treats as the load-bearing content.
